## Future assessment record

The [local pilot validation record](PILOT-VALIDATION-2026-10-01.md) provides executed, revision-bound evidence for selected cases. Its coverage table explains why complete requirements above remain unassessed.

Record these fields for an adopting product:

| Field | What to provide |
|---|---|
| Specification | Document version and exact source commit |
| Implementation | Repository/build revision and deployed configuration under review |
| Scope | Operations, consequence classes, providers, and enabled capabilities |
| Applicability | Included rules and justified exclusions |
| Evidence | Executed results and separately reviewed procedures for each applicable rule |
| Reviewer and date | Responsible reviewer and assessment time |
| Departures and gaps | Recommendation rationale, failures, missing evidence, residual risk |
| Conclusion | Precisely bounded claim supported by that evidence |

A full scoped claim cannot omit an unmet applicable mandatory obligation. Documentation publication, a UI component, a test count, or a framework logo is not certification.

## Maintaining the map

When a requirement changes, review the procedure and associated threats in the same change. Keep existing IDs stable; do not reuse retired IDs for unrelated requirements.

The documentation checker detects missing, duplicate, and unknown identifiers and matrix references. It cannot judge whether a procedure is sufficient or whether a claimed runtime result is true.
